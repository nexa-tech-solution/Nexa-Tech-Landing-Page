Utility apps grow by default. Someone who resizes images also wants to crop them, then add text, then apply filters, and soon the app is a worse version of a full editor. For Quick Image PDF Resizer we kept a written decision log instead. This post shares it, lightly edited.

The one-sentence purpose

Quick Image PDF Resizer

Make files the right size and format for wherever they need to go, quickly, on the device.

Every request gets checked against that sentence. If it helps the job, it is a candidate. If it changes the job, it needs a real discussion.

The decision log

RequestDecisionReason

Merge and split PDFsYesForms often need pages combined or removed
Simple cropLaterHelps the job, but only once resize is polished
Filters and colour tweaksNoEditing, not preparing a file
Text and stickersNoA different app entirely
Cloud folders and accountsNoBreaks "on the device"
Edit text inside PDFsNoHard to do well; heavier tools exist

How a request moves through the log

Why write it down at all

Saying no is easy when you are tired and hard when a request is reasonable. A written log takes the decision away from whoever happens to be in the conversation, and the one-line reasons stop the same debate recurring every few weeks.

A short app is easy to explain in one sentence. That sentence is also the store listing.

The log is not permanent

A few items have moved from "later" to "yes" when enough people needed them for the core job. Each move was a decision, not a drift, and the app still does what its name says.
